# REMINDaler

電話アプリ風のテンキーから日時を入力し、録音したメッセージを指定時刻に「着信」させる Android アプリです。

- アプリ名: `REMINDaler`
- パッケージ: `com.mine.remindaler`
- 対応: Android 10 (API 29) 以上のスマートフォン・タブレット
- 画面サイズ・向き・フォントサイズに応じてレイアウトを調整します
- 配布用成果物: `REMINDaler-distribution.apk`（debug署名・非デバッグ可能・インストール可能）
- 開発用成果物: `REMINDaler-debug.apk`（デバッグ可能。配布用には使わないでください）

## 使い方

1. アプリを開くとテンキーが表示されます。
2. `MMDDhhmm` の8桁で日時を入力します（例: `10220830` → 10月22日 08:30）。
   - 過去の日時を入力した場合は翌年として扱われ、プレビューに年が表示されます。
   - 右下の ⌫ キーで1文字削除、「クリア」で全消去できます。
   - 入力が空のときに `*` を押すと、現在の月 → 日 → 時の順に2桁ずつ入力します（4回目以降は何もしません）。
   - 数字の手入力・⌫・「クリア」で `*` の入力状態はリセットされます。
3. 緑の「発信」ボタンをタップすると録音が始まります。
4. メッセージを話し、赤い受話器ボタンをタップすると予約が確定します（最長60秒で自動停止）。
5. 指定時刻になると着信画面が表示され、着信音・バイブのあと「応答」で録音が再生されます（ロック中は端末解除が必要です）。
6. 右上の一覧アイコンから予約の確認・再生・テスト着信・削除ができます。

## インストール

### 端末へ直接コピーする場合

1. `REMINDaler-distribution.apk` を端末へ転送します。
2. 端末の設定で「提供元不明のアプリ」を許可します。
3. ファイル管理アプリから APK を開いてインストールします。

### adb を使う場合

```bash
adb install -r REMINDaler-distribution.apk
```

### 配布APKについて

- 配布用APKは `distribution` ビルドで、debug署名のまま `android:debuggable=false` にしています。
- 開発用の `REMINDaler-debug.apk` はデバッグ可能なため、配布しないでください。
- 同じ開発環境の debug keystore でビルドしたAPKであれば上書き更新できます。
- 別のPCでビルドしたAPKへ更新する場合は、署名が異なるため一度アンインストールが必要です。
- 長期配布する場合は、release 用の署名鍵を作成して `applicationId` とセットで保管することを推奨します。

## 初回セットアップ（重要）

アプリ右上の歯車アイコン →「設定と権限」を開き、以下を許可してください。

| 項目 | 用途 | 必須 |
|---|---|---|
| マイク | メッセージの録音 | 必須 |
| 通知 | 指定時刻の着信通知 | 必須 |
| 全画面通知 | ロック画面でも電話風の着信画面を表示 | 推奨 |
| 正確なアラーム | 指定時刻どおりに発火 | 推奨（未許可時は数分遅れる場合あり） |
| 電池の最適化除外 | スリープ中の着信を安定させる | 推奨 |

補足:

- 全画面通知が許可されない場合でも、通知の「応答」ボタンから録音を再生できます（ロック中は端末解除が必要です）。
- 端末の**アラーム音量**が 0 の場合は音が鳴りません。音量ボタンで確認してください。
- マナーモード／Do Not Disturb で「アラーム」が許可されていないと音が鳴らないことがあります。

## 動作確認のしかた

1. 現在時刻の1〜2分後を入力して予約します。
2. 画面を消して待ちます。
3. 着信画面が出ることを確認します。
4. 「応答」で録音が再生されることを確認します（ロック中は端末解除後に再生されます）。

すぐに着信画面だけを確認したい場合は、予約一覧の「テスト着信」を使います。
テスト着信は本番の予約状態を消費しません（録音の再生と着信 UI のみ確認できます）。

## ビルド

このリポジトリには Gradle Wrapper が含まれています。

```bash
export JAVA_HOME=/path/to/jdk21
export ANDROID_HOME=/path/to/android-sdk   # platform 36 / build-tools 36

# 配布用（非デバッグ可能・debug署名）
./gradlew :app:assembleDistribution

# 開発用（デバッグ可能）
./gradlew :app:assembleDebug
```

APK の出力先:

```
app/build/outputs/apk/distribution/app-distribution.apk   # 配布用
app/build/outputs/apk/debug/app-debug.apk                 # 開発用
```

Android Studio で開く場合は、そのままプロジェクトディレクトリを指定してください。

- AGP 8.13.2 / Gradle 8.13 / Kotlin 2.2.21
- compileSdk 36 / targetSdk 36 / minSdk 29

## 構成

```
app/src/main/java/com/mine/remindaler/
├── MainActivity.kt              画面切り替え・権限状態
├── IncomingCallActivity.kt      着信画面・着信音・録音再生
├── RemindalerApp.kt             Application / リポジトリ初期化
├── alarm/
│   ├── AlarmScheduler.kt        AlarmManager への登録
│   ├── AlarmReceiver.kt         発火時の通知
│   ├── DeclineReceiver.kt       通知の「拒否」
│   └── BootReceiver.kt          再起動・時刻変更後の再登録
├── audio/
│   ├── AudioRecorder.kt         MediaRecorder ラッパー
│   └── PreviewPlayer.kt         一覧からの試聴
├── data/
│   ├── Reminder.kt              予約モデル
│   └── ReminderRepository.kt    JSON 永続化
├── notify/NotificationHelper.kt 通知チャンネル・全画面通知
└── ui/                          Compose 画面・日時パーサ・権限 UI
```

- 録音ファイル: アプリ内部ストレージ `files/recordings/`
- 予約データ: `files/reminders.json`
- 予約は端末再起動後に `BOOT_COMPLETED` で再登録されます。
- アプリを「強制停止」した場合は OS がアラームを解除するため、再度アプリを開くまで着信しません。

## 端末ごとの注意

- メーカー独自の省電力設定や自動起動制限（Xiaomi / OPPO / vivo / HUAWEI / Samsung など）により、画面オフ時の着信が遅れたり、再起動後に予約が復元されない場合があります。設定アプリの「バッテリー」や「アプリの自動起動」も確認してください。
- Android 14 以降では、全画面通知が許可されない場合があります。その場合は通知の「応答」から録音を再生できます（ロック中は端末解除が必要です）。
- 正確なアラームが許可されない場合、着信が数分遅れることがあります。
- Android 10〜12 では通知の権限ダイアログはありませんが、端末設定で通知をOFFにすると着信通知は表示されません。

## 既知の制限

- 端末メーカーの省電力設定により、バックグラウンド起動が止められる場合があります。設定アプリのバッテリー設定も併せて確認してください。
- 全画面通知が無効な場合は、通知の「応答」からの再生になります（ロック中は端末解除が必要です。通知は自動では消えません。応答／拒否で処理してください）。
- タイムゾーンを変更した場合、予約時刻は絶対時刻のまま維持されます。
- デバッグ署名のため、別の PC で再ビルドした APK とは上書きインストールできません（一度アンインストールが必要です）。
